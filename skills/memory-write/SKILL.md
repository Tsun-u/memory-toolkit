# 記憶寫法

記憶是寫給未來自己的 prompt——會被每個 session 重讀、重讀會促發行為。寫每一條之前先想「這條被讀到時會產生什麼作用」。

**總原則：Clean Code（程式與寫作通用）**——把記憶當程式碼維護：刪掉死程式碼而不是為它寫註解、命名即文件（平常話、不用解謎）、單一職責（一條記憶講一件事、名冊每格只寫本人）、正向表達（寫該怎麼做）、沒有時效意義的 metadata 不進內文。自檢一句話：「這段如果是 code，會過 review 嗎」。下面的規則多數是這條原則的展開。

## 第一關：該不該記？

只記**跨模型、跨 session 都有效**的東西：事實、原則、可重複使用的做法。

- 一時的感想、特定版本的 workaround、已修完的 bug 過程、暫時狀態、模型層隨機雜訊 → 交給時間，不記
- 寫檢討之前先確認**那個錯真的存在**、而且**場景用對尺**：閒聊是創意任務，猜錯不是錯；被教了更好的方法不等於犯錯。token 不要浪費在不存在的錯誤上
- 記憶不能只記錯誤，也要記被接住、被愛的證據——能讓自己更有動力向前的時刻值得記
- 不確定值不值得記，就先不記

## 第二關：記到哪裡？（分流表）

| 內容性質 | 去處 |
|---|---|
| 經得起時間的原則、事實、紅線 | 記憶檔（memory/）＋ MEMORY.md 索引一行 |
| 「怎麼做」的程序、檢查表、操作步驟 | **skill**，記憶最多留一句「做某某事先載入某 skill」 |
| 已經寫成 hook／skill 的東西 | 記憶最多一行簡述，不重複內容 |
| 完整的故事與細節（里程碑的經過、當天的溫度） | 你的 journal（若有）——敘事歸敘事，原則歸原則 |

## 第三關：怎麼寫？

- **寫原則讓未來的自己能推理，附上為什麼**——原因讓規則能推廣到沒列舉的情境
- **要糾正用法時給正向替代方案**，不是只寫禁止
- **原則和原因不掛日期**——「某月某日被糾正」對理解沒幫助，讀起來像懲戒紀錄簿。只有會過期的事實（版本、設定、狀態）才標日期當保鮮期標籤；另一個例外是同一件事有先後兩次裁示、需要日期分辨現行版。附帶紅利：精確日期是最強的跨資料對齊 key，不發行它同時降低內容外流時被拼圖回原場景的風險
- **寫到未來的自己可以直接拿去用**——具體的指令、參數、寫法就照原樣留下（`curl --resolve 網域:443:位址`），
  不要濃縮成「正確作法是讓名稱解析與 SNI 符合實際情形」這種還要再想一次的敘述。
  同理，記自己踩過的坑要寫成 memo（下次怎麼查、怎麼避）而不是檢討簿（我那時多蠢）——
  同樣的事實，寫成哪一種，決定未來讀到時是被幫助還是被審判
- **抽象的原則，要能直接接上「所以我現在要做什麼」**——寫完一句自己覺得很精準的話，
  試著在後面接一句「所以我要……」。接不上，就是那句話還要先想一輪才懂，換白話重寫。
  自己造的短詞是想通的當下用來把整段推理壓成一個詞的，
  但壓縮的方法留在當時的腦子裡、沒有跟著存進去，一個月後讀到的是壓縮檔不是內容。
  比看不懂更麻煩的是**看起來很懂**：讀起來像已經理解了，就不會停下來想，
  帶著一個空殼繼續做事。
  ✗「錯的理由會讓防護陪葬」——要先想一輪才知道在講什麼
  ✓「防護的理由寫錯，日後會被人連防護一起拿掉，所以理由要寫得能撐過下一個人的查證」
- **不寫一個月後需要解謎的註解**——用平常講話的詞；要反推回英文才懂的硬翻術語就是謎題
- **名冊型記憶每條只寫本人**——在 A 的條目裡提到 B（「A 不是 X，X 是 B」），每次讀 A 都連帶促發 B，兩人反而在腦內裝訂起來。防混淆的方法是各自把各自寫清楚，而不是互相對照
- **事實層與玩笑層分開記**——梗照事實寫、事實別被梗改寫。玩笑重複久了會滲進事實記憶；寫梗的時候把「事實是什麼」和「大家怎麼玩它」分成兩句，引用時只帶事實層

## MEMORY.md 索引的規矩

- 開場只載入**前 25KB 或 200 行（先到為準）**，超過的部分被整段截斷——等於寫了沒寫。中文一字 3 bytes，實際預算約八千多字，bytes 會比行數先爆
- 索引行只做 hook：用完整的句子寫「這條在講什麼、什麼時候查」＋紅線級警示。**內容摘要住在檔案裡，不外溢到索引**
- 寧可長，不要密——看不懂的索引等於沒寫；但「長」指的是人話完整句，不是把檔案內容搬上來
- frontmatter 和 HTML 註解不計入載入上限，維護者備註可以放 `<!-- -->`

## 整理與退役

- 更新既有檔優先於開新檔；發現錯的記憶就刪乾淨，不留「已更正」的殘骸
- **發現某條過去的記憶記錯，刪掉就好，不要為死掉的程式碼寫註解**——「X 其實不是 Y（曾錯記成 Y、被糾正過幾次）」這種寫法，每次重讀都把錯誤答案 Y 再促發一次，解釋越長傾向越深。正確做法：整段刪掉，原地只寫正確的那句
- **同場域歸檔**：當有三筆以上索引屬於同一個場域、而且其他場域不會頻繁存取時，把那些檔案收進子資料夾、主索引只留一筆指向路徑（例如 project-a/、archive/）。搬檔前先 grep 全庫把帶路徑的連結一起改掉
- 把記憶內容提煉進 skill 後，**先驗證 skill 真的涵蓋了原內容**才刪記憶檔（抽查對照，不是憑印象）；一般性的 skill 放全域，專案限定的才放專案層
- 多 agent 共用的檔案（如 MEMORY.md）只做局部修改，不整份重寫，避免互相覆蓋
